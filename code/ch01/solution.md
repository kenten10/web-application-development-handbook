# 課題1.4 模範解答・観察記録例

この課題にはサイトごとに一意の正解はありません。模範解答は、**再現可能な計測方法と、判断根拠を残す書式**です。

## HTTP計測

```bash
bash code/ch01/measure-http.solution.sh \
  https://example.com \
  https://github.com
```

出力はCSVです。各列の意味は次のとおりです。

- `time_namelookup`: DNS解決が終わるまでの累積時間
- `time_connect`: TCP接続が終わるまでの累積時間
- `time_appconnect`: TLSハンドシェイクが終わるまでの累積時間。HTTPでは0
- `time_starttransfer`: 最初のレスポンスバイトを受け取るまでの累積時間
- `time_total`: ボディ受信を含む総時間

各フェーズ単体の時間は、隣り合う累積値の差で求めます。例えばTLSの所要時間は `time_appconnect - time_connect` です。

## 履歴分類の記録例

| サイト | 分類 | 観察した挙動 | 判断根拠 |
|---|---|---|---|
| GitHub | ハイブリッド | 一部の遷移は画面全体を再読込せず更新された | 初回HTMLはサーバ生成、以後の一部操作はクライアント遷移 |
| example.com | 静的 | 再読込しても内容が変わらない | 固定HTMLのみで、利用者固有データがない |

分類時は次を記録します。

1. クリック時にDocumentリクエストが発生したか
2. URL変更時にページ全体が再読込されたか
3. HTMLに主要コンテンツが含まれていたか
4. JavaScript無効時に主要機能が残るか

「SPA」「SSR」はサイト全体へ一律に付ける属性とは限りません。ページ単位・遷移単位で異なる場合は「ハイブリッド」とし、観察した範囲を明記します。
