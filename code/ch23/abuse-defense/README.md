# 課題23.10: 濫用対策の鍵と応答の設計を破って塞ぐ (★★★)

## 目的

分散した Credential Stuffing の素通り、応答の差によるアカウント列挙、固定ロックによる締め出し、`Retry-After` を伴わない拒否という4件を再現し、層を重ねた実装へ差し替えると1件も残らず、かつ平常時の正しいログインは通り続けることを確かめる。

## 課題23.5 との違い

課題23.5 はレート制限の**アルゴリズム**（Token Bucket / Sliding Window）を実装します。本課題が扱うのはその周りにある判断 ―― 何を鍵にするか、しきい値を超えたら何をするか、応答から何が漏れるか ―― であり、アルゴリズムは固定窓の最小実装で足ります。

## 安全上の注意

資格情報も漏洩リストもすべて架空の値であり、実在のものではありません。攻撃の模擬はプロセス内で完結し、ネットワークへは一切出ません。**自分が所有していない、あるいは許可を得ていないシステムに対して同種の試行を行ってはいけません。** しきい値、チャレンジの方式、漏洩資格情報の照合先の選定は、実際の利用者層と法務の判断を伴います（13.25、23.27、30.16）。
